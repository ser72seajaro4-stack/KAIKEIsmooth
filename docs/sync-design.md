# データの移行・複数端末での同期（設計）

2026年10月30日 追加。画面は S09「データの移行・同期」（ホーム右上の「移行・同期」ボタン、またはホーム下部の「バックアップ・同期」から開く）。

要件定義書ver.3では「データはサーバーに送信しない」「機種変更時のデータ引継ぎは開発範囲外」としていたが、利用者が自分で選んだ場合に限り、移行・同期できるようにした。同期を始めない限り、今までどおりデータは端末の中だけに保存される。

## 1. 2つの方法

| 方法 | 使う場面 | サーバー | 仕組み |
| --- | --- | --- | --- |
| ファイルで移す（バックアップ） | 機種変更・ブラウザを変える前 | 不要 | データを1つのJSONファイル（`kaikei-smooth-backup-YYYYMMDD.json`）に保存し、新しい端末で読み込む。ファイルの代わりにテキストでコピーして、メール等で送ることもできる |
| 同期 | スマホとタブレットなど、複数の端末で同じデータを使い続ける | 必要（PHP） | 同期コードごとにサーバーにデータを置き、同じコードを入れた端末どうしで共有する |

## 2. 同期の流れ

1. 端末Aで「この端末で同期を始める」→ 同期コード（例：`K7QM-2XPA-9DRT-HV4N`）とQRコードが出る。
2. 端末Bで同期コードを入れる、またはQRコードを読み取る（`index.html#sync=コード` が開き、つなぐか聞かれる）。
3. 端末Bにもともとあったデータは、同期先のデータと合わせられる（消えない）。
4. 以降は、データを変えて3秒後・本アプリを開いた時・他のアプリから戻った時・通信が戻った時に、自動で同期する。「今すぐ同期」でも同期できる。

同期コード：16文字（32種類の文字。0/O・1/I など見間違えやすい文字は使わない）＝約80ビットの乱数。ログインの代わりなので、知っている人はデータを見たり変えたりできる。人に教えないよう画面に表示している。

## 3. 合わせ方（マージ）

js/sync.js `mergeData()`。端末側で合わせ、サーバーは保存するだけ。

| データ | 合わせ方 |
| --- | --- |
| アプリ・ポイント・お店 | 1件ずつ `updatedAt`（最後に変わった時刻）を比べ、新しい方を残す。`updatedAt` は storage.js の `save()` が、中身が変わった記録にだけ自動で付ける |
| 削除 | 削除した記録のIDと時刻を `syncTombstones` に残す。削除の方が新しければ、ほかの端末に残っていても消す（復活しない）。90日たった削除記録は捨てる |
| 起動履歴 | 全端末の分を合わせる。30日より古いもの・削除したアプリの分は除く |
| お店の紐付け | 削除されたアプリへの紐付けは外す |
| 開けた起動方法（`launch`） | アプリの記録の一部として、新しい方を残す |

例：端末Aでポイント1を削除し、同時に端末Bでポイント2を編集した → どちらの変更も残る（テストで確認済み）。
同じ記録を2台で同時に変えた場合は、後から変えた方が残る。

## 4. サーバー（api/sync.php）

- POST・JSONで `get` / `put` / `delete` の3つだけ。データは `data/sync/<同期コードのハッシュ>.json` に保存する。
- 書き込みの衝突は版数（version）で防ぐ：`put` の `baseVersion` がサーバーの版数と違えば 409 を返し、端末はもう一度取り直して合わせる（最大3回）。
- `data/.htaccess`（`Require all denied`）で、保存したファイルをWebから直接読めないようにしている（Apache・XAMPP用）。
- 送れる大きさは4MBまで（アイコン画像を入れても足りる大きさ）。同期コードの形が違うものは受け付けない。
- 必要なもの：PHP 7.4以上（XAMPPのPHPでよい）、`data` フォルダへの書き込み権限。データベースは使わない。

## 5. 制限・注意

- GitHub Pages など、PHPが動かない場所では同期は使えない（「サーバーにつながりませんでした」と出る）。バックアップは使える。
- localhost で開いている時のQRコードは、そのパソコンでしか開けない。スマホからはパソコンのIPアドレス（例：`http://192.168.0.10/KAIKEI%20smooth2/`）で開く。
- 同期コードを忘れた場合、同期中のほかの端末の「データの移行・同期」画面で確認できる。全端末でやめてしまうと分からなくなる。
- 不正利用の対策（同じIPからの大量アクセスの制限など）は入れていない。学内・自宅のサーバーで使う前提。インターネットに公開する場合は追加が必要。
- 通信はHTTPSにすること（同期コードとデータが通信の途中で見えないように）。

## 6. 確認したこと（自動テスト：PHPの開発用サーバー＋2台の端末を想定）

- 端末Aで同期開始 → 端末BでQRコードのURLから参加 → 両方のデータが合わさる
- 片方での削除・もう片方での編集が、両方に正しく反映される
- バックアップファイルの保存 → 別の端末で読み込み（合わせる）
- 会計スムーズApp以外のファイル・短すぎるコード・存在しないコードはエラーを表示
- API：GET（405）、コードの形が違う（400）、版数の衝突（409）、データの形が違う（400）、4MB超（413）、削除（200）
