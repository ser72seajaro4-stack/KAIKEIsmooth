### 候補を全部使う（自動で順番に試して、開けた方法を覚える）

候補が複数あるアプリ（一覧にないアプリで ✎ からURLスキームを入れた場合など）は、全部の候補を登録しておき、外れたら自動で次の候補を試す（home.js `openApp()`・`attemptLaunch()`）。利用者に「開けたか」を聞くことはしない。

1. 開けた方法を覚えていれば、それで開く。
2. まだなら、前回までに外れていない候補から試す。
   - 画面が他のアプリに切り替わった（visibilitychange・pagehide）→ 開けたとみなして、その方法を覚える。
   - 2.5秒たっても切り替わらなかった → 外れ。すぐ次の候補を自動で試す。
   - Androidは、すべての intent URL の `S.browser_fallback_url` を本アプリのURL（`#kf=アプリID.番号`）にしておく。外れた時にGoogle Playへ飛ばずに本アプリに戻るので、iPhoneと同じように外れを判定できる（Google Playに飛ぶと画面が切り替わり、「開けた」と間違えて覚えてしまうため）。
3. 候補が全部外れたら、ストアのページを開く（ブラウザに止められた時のために「App Storeで開く」ボタンも出す）。
   - ストアから本アプリに戻ってきた時に「↻ 更新して開く」ボタンを出す。ストアでインストールした後に押すと、開けなかった方法の記録を消して、すぐ直接開く。
   - 全部外れたアプリは、次からはストアのページを開く。アプリを後からインストールした時は、アプリ管理画面の「↻ 起動方法を更新」で、開けなかった方法の記録をまとめて消せる（開けた方法の記録は残す）。
4. 覚えていた方法で開けなくなった時は、最初の候補から試し直す。

外れとして記録するのは、タップした直後の1回目だけ。自動で続けて試した2つ目以降は、ブラウザに止められて開けなかっただけの可能性があるため記録しない（次のタップで改めて試す）。
`blur` は「切り替わった」に数えない（iPhoneで「アドレスが無効です」が出ただけでも起きることがあり、外れを当たりと間違えるため）。

覚えた結果は、端末の種類（iPhone／Android）ごとにアプリのデータ（`apps` の `launch`）に保存する。画面には表示しない。✎ でスキームを入れ直すと、試した結果はやり直しになる。

### テストのしかた

1. スマホで `scheme-test.html` を開く（本番の画面からはリンクしていない）。
2. 候補をタップしてアプリが開くか試し、○か×を押す。候補にないスキームは「ほかの候補を入力」で追加して試せる。
3. 「結果をコピー」で結果のテキストをコピーして送る（iPhoneとAndroidで別々に記録される）。
4. 結果をもとに `tools/apps_data.py` の `SCHEMES` を直し（開けたものは `('T', [スキーム], メモ)`、開けなかったものは `('N', [], メモ)`）、`python3 tools/build_presets.py` を実行する。

今の一覧では、ストアを開くアプリ（N）は候補が空のため、テスト用ページには候補が出ない。試したい時は「ほかの候補を入力」で入れる。

Androidのテストでは、パッケージ名を指定したintentで開く。スキームが違う時はGoogle Playが開くので、その場合は×にする。

### 登録済みのアプリのスキームを変える

アプリ管理画面の ✎ から、登録済みのアプリのURLスキームを書き換えられる。プリセットのアプリは候補がボタンで表示される。空にすると、ストアの「開く」から起動する。

## 3. 起動のしかた（iPhoneとAndroidの違い）

| | iPhone（Safari） | Android（Chrome） |
| --- | --- | --- |
| アプリが入っているかを調べる | できない | できない（ただしintent URLならChromeが代わりに判断する） |
| URLスキームで起動に失敗した時 | Safariが「アドレスが無効です」と表示するだけで、ページには知らされない | intent URLの `S.browser_fallback_url` に書いたページを、Chromeが自動で開く |
| URLスキームなしで直接起動 | できない | できない（Chromeは BROWSABLE な画面しか開けず、ホーム画面のアイコンと同じ起動はできない） |
| ストアアプリを直接開くURL | `itms-apps://apps.apple.com/jp/app/id〇〇` | `intent://details?id=〇〇#Intent;scheme=market;package=com.android.vending;S.browser_fallback_url=…;end` |
| 失敗後に自動でストアへ移動 | しない（タップ以外からの移動は止められることがあるため、ボタンを出す） | Chromeが自動で行う |

### 本アプリの動き（home.js `openApp()`）

**iPhone**
1. URLスキームがある → 直接起動（1タップ）。2.5秒たっても画面が切り替わらなければ、「App Storeで開く」ボタン付きのメッセージを出す。
2. URLスキームがない → App Storeアプリでそのアプリのページを開く。インストール済みなら「開く」で起動（2タップ）。未インストールなら「入手」できる。

**Android**
1. URLスキームとパッケージ名がある → intent URLで直接起動（1タップ）。起動できなければChromeが自動でGoogle Playのページを開く。
2. URLスキームがない → Google Playアプリでそのアプリのページを開く。インストール済みなら「開く」で起動（2タップ）。Google Playがない端末では、ChromeがWeb版のGoogle Playを開く。

**その他（PC）**：ストアのWebページを別タブで開く。

### 一覧の表示
- iPhoneではApp Storeで配信されていないアプリ（モバイルICOCA・楽天Edy・Google ウォレット）を表示しない。
- AndroidではGoogle Playで配信されていないアプリ（Apple Wallet）を表示しない。

## 4. 実機で確認すること

- iPhone：`itms-apps://` でApp Storeアプリが開くか（Safari・ホーム画面に追加した状態の両方）。開くまでに確認のダイアログが出るか。
- iPhone：`shoebox://` でウォレットが開くか。`paypal://` でPayPalが開くか。
- Android：Google Playアプリのページが開くか。PayPalのintent URLで直接起動し、未インストール時はGoogle Playに切り替わるか。
- 起動失敗の判定時間（home.js `LAUNCH_WAIT_MS`、2.5秒）が短すぎないか。
